# Защита профилей и заявок (v35)

## Что проверяется сервером

- Личные API, `/stats` и `/save` требуют подписанный Telegram `initData`.
  Проверяются HMAC, срок сессии (24 часа), повторяющиеся поля, положительный
  целочисленный ID пользователя. Боты, объекты каналов и некорректные профили
  отклоняются. Личный аккаунт может открыть приложение по ссылке из канала.
- Владелец сохранённого результата берётся из проверенной подписи, а не
  из присланного `user_id` или ника. Старая статистика выбирается строго по ID;
  сравнения с отсутствующим `username` больше нет.
- `/stats` показывает только свою подробную статистику. В публичном профиле,
  поиске и рейтинге чужие результаты и награды доступны только подтверждённым
  друзьям и только при согласии владельца на публикацию. В ходе самого баттла
  соперники по-прежнему видят счёт текущего матча.
- База, результаты, решения и секреты не раздаются как статические файлы.
  Личные ответы имеют `Cache-Control: private, no-store`. У сохраняемых
  `community.json` и `results.json` права `0600`.

## Друзья и блокировки

- Поиск — по полному публичному никнейму, без поиска по фрагменту.
- Только получатель может нажать «Принять». Встречное нажатие «Добавить»
  больше не принимает заявку неявно.
- Максимум 5 новых заявок за скользящий час, 20 за скользящие сутки.
  После отклонения повторная заявка этому человеку запрещена 7 дней.
  Ограничения сохраняются после перезапуска сервиса.
- В кабинете можно отдельно запретить новые заявки, сохранив текущих друзей
  и участие в рейтинге. Старые ожидающие заявки остаются: можно отклонить
  их или заблокировать отправителя. По умолчанию прежняя доступность заявок
  сохранена для существующих профилей.
- «Заблокировать» доступно в заявке, списке друзей и чужом профиле. Требуется
  подтверждение. Прекращаются дружба и незавершённые приглашения; запрещаются
  сообщения, новые заявки, приглашения и поиск друг друга. Заблокированные
  участники не подбираются друг другу в новых случайных баттлах.
- Блокировка не отменяет уже начавшийся матч: выход из него выполняется
  существующим действием «Покинуть баттл», с прежними правилами результата.
- Снять собственную блокировку можно в разделе друзей. Это не восстанавливает
  дружбу и старые заявки. Чужую блокировку снять нельзя.
- Поиск ограничен 20 запросами в минуту, все личные API — 240 запросами
  в минуту на Telegram ID в одном процессе. Эти ограничения не заменяют WAF
  и общий лимитер при работе нескольких экземпляров приложения.

## Границы защиты

Подпись Telegram подтверждает аккаунт, но не личность человека и не отсутствие
автоматизации. Пользователь может назвать себя как канал. Нельзя обещать
«только реальные люди» по одному нику, фото или полю `is_bot`.

Этот выпуск не является полным аудитом всей инфраструктуры. Он не добавляет
шифрование диска, двухфакторную авторизацию GitHub/Railway/Telegram, внешнюю
защиту от DDoS, резервное копирование или миграцию JSON в СУБД. Админский
доступ по разрешённым Telegram-именам оставлен без изменения; следующий шаг —
закрепить его исключительно за проверенными числовыми ID владельца.
Также начисление тренировочных монет и проверка правильности первой части
нуждаются в отдельном переносе авторитетного расчёта с клиента на сервер.

Имена и аватары добровольных публичных профилей остаются доступны участникам;
загруженные аватары раздаются по непредсказуемым URL. Блокировка не может
удалить ранее сохранённые у другого человека изображения или сообщения.

## Проверка перед выпуском

`python3 -m unittest discover -s tests -q`

`node tests/test_privacy_ui.cjs` — изолированные проверки клиентских обработчиков,
не заменяющие визуальный тест на настоящем телефоне.

`tests/test_security.py` использует только искусственные аккаунты и временные
файлы. Тесты отправки уведомлений заменяют Telegram-отправку заглушкой.
Не запускать диагностические запросы с поддельными личностями на боевом сервере.
